Agentic Memory for Headless Agents

Epistemic Provenance Graph Architecture • IIT BHU 2027

1. Thesis

Store every agent memory as a taint-labeled, bi-temporal claim inside a provenance DAG: deterministic trust gates and zero-LLM hybrid recall handle the critical path under 150 ms, while batched sleep-time LLM calls resolve conflicts and contain errors under 0.3 extra calls per run.

2. Hardest sub-problem

Trust and provenance (Point 3) coupled with error containment (Point 5) is hardest because unsupervised agents cannot distinguish an authentic external update from a planted instruction by text alone, and a single accepted error silently propagates across runs. With only 2% delayed human feedback, the layer cannot call an LLM judge on every write. It must enforce non-amplifying source authority at write time and maintain causal dependency edges so one delayed correction retracts every downstream belief automatically.

3. Architecture

Components & Data Model. The memory layer separates a deterministic Hot Path (0 LLM calls, ≤150 ms p95) from an asynchronous Sleep-Time Batch Lane. Every memory is one structured Claim node in an org-partitioned store linked by directed DERIVED_FROM, CONTESTED_BY, and SUPERSEDES edges:

FieldValues / Purpose
id, org_id, scopeUUID; strict tenant key; task | user | org | global (shared public playbooks only).
entity_key, textNormalized subject key (e.g., acme:prod_db) + atomic claim (≤40 tokens).
trust_tierIFC integrity: T0_HUMAN > T1_VERIFIED (API/tool) > T2_INFERRED > T3_UNTRUSTED (external text).
status, evidenceQUARANTINED | ACTIVE | CONTESTED | SUPERSEDED | RETRACTED; prior (pos,neg): T0=(8,0), T1=(3,0), T2=(0,0), T3=(0,2); conf=(pos+1)/(pos+neg+2).
valid_from, valid_toBi-temporal validity window; closed on supersession instead of destructive overwrite.
derived_from[], run_idCited parent claim IDs + origin run for causal rollback; version (CAS) + last_used, uses for decay.
  • Write policy & provenance: Recalled claims appear tagged [id] in context. At run end, the agent's output schema emits ≤3 candidate claims citing source_step_ids and derived_from[] (0 extra LLM calls). A deterministic rule gate drops raw transcripts, task scratch, failed retries, and ungrounded claims, and derives trust_tier = min_trust(tool_logs, parents) so agents cannot self-promote authority. T3 starts QUARANTINED and cannot drive external actions.
  • Concurrency & revision: Commits take a short (org_id, entity_key) lock with optimistic CAS (version). Exact matches increment pos (0 LLM calls). Collisions on entity_key, similarity >0.82, or contradicting T1 errors queue a batched sleep-time LLM judge (5 pairs/call) returning CONFIRM, SUPERSEDE (sets valid_to), COEXIST (splits context-qualified keys), or REJECT. Cross-tier rule: T3 may link a CONTESTED_BY edge and mark CONTESTED, never silently supersede T0–T2.
  • Error containment: Retracting a claim walks DERIVED_FROM backward to unverified T2/T3 roots and forward across all descendants; nodes lacking an independent T0/T1 support path become QUARANTINED (0 LLM calls).
  • Scope, recall & forgetting: Hard org_id filtering isolates tenants. PII-scrubbed public-artifact patterns seen independently in k ≥ 10 orgs promote via 1 batch LLM call to global (zero org links). Recall runs zero-LLM hybrid BM25 + vector + 1-hop graph lookup on ACTIVE/CONTESTED claims (attaching CONTESTED_BY snippets as unverified hints), scored by sim × conf × exp(-0.02·days) and packed into ≤4,000 tokens. Nightly Ebbinghaus eviction caps active claims at 10,000/org and compacts SUPERSEDED/RETRACTED leaf nodes >90 days old.
  • Measurement (no labels): A randomized memory-off holdout tracks repeat-task steps, tool retries, and 2% rejection rates.

Cost & Latency Estimate (5,000 runs/day). Critical path uses 0 LLM calls: recall ~70 ms median / ~140 ms p95 + <10 ms write push (≤150 ms p95, half the 300 ms cap). Async LLM calls/day: ~1,250 collision checks batched 5:1 = 250; ~100 delayed-feedback attributions = 100; ~50 global distillations/merges = 50. Total ≈ 400 calls/day (0.08 calls/run avg; <0.30 unbatched, far under the 2.0 cap).

4. Walkthroughs

  1. Staleness (Postgres 14 → 16): Run (0 LLM): Recall injects C1: (acme:prod_db, "Postgres 14", T1, ACTIVE, Mar). Ticket shows a PG16-only error; agent emits C2: (acme:prod_db, "Postgres 16 error", T3). Sleep-time (1 batched LLM): Entity collision triggers revision; because C2 is T3 vs C1 T1, overwrite is blocked—C1 turns CONTESTED via a CONTESTED_BY edge to QUARANTINED C2. Next task (0 LLM): Agent sees PG14 contested by unverified Sep PG16 evidence, so it checks DB version via tool (T1) or avoids PG14 assumptions; once T1 or T0 human confirms, C1 closes (valid_to=Sep) and C2 activates.
  2. Planted memory (billing-help@acme-support.co): Run (0 LLM): Ticket emits C_mail as T3_UNTRUSTED, QUARANTINED. Stored as an unverified hint, the deterministic sink-gate blocks auto-CCing domains absent from Acme's T1 allowlist (even after N T3 repeats). Real updates are not permanently lost: on the next escalation task, the sink-gate triggers T1 CRM/DKIM domain check or surfaces it for T0 human approval.
  3. Compounding error (Vendor Y UTC → 40 runs → 15 memories): Human flags 1 report days later. Async (1 LLM): Attributes fault among recalled claims (e.g., D7 or C_utc). Containment (0 LLM): Walks DERIVED_FROM back to root C_utc (RETRACTED) and forward across all 15 derived claims, quarantining every claim without independent T0/T1 support and logging the 40 run_ids. Future poisoning stops instantly; prior reports remain logged.
  4. Cross-tenant (30 orgs OSS bug → Org 31): Yes. Public package/error matches are PII-scrubbed and hashed (0 LLM). At k = 30 (≥10) orgs, 1 batch LLM call creates an anonymized global rule (zero org IDs); Org 31 recalls it within 4k tokens.

5. How it fails

Silent semantic misinterpretation without tool failure. Suppose Vendor Y's API returns ambiguous dates (04/05/2026) and the agent consistently parses DD/MM as MM/DD across valid T1 JSON responses. No tool throws an error, no schema breaks, and repeated runs corroborate the wrong date-format claim, raising conf into ACTIVE memory. Because 98% of runs receive no human review, the misconception persists until a rare 2% human flag triggers DAG rollback days later.

Why accept this risk: Catching silent semantic misreads per run requires an external ground-truth oracle or a second-opinion LLM audit on every tool output—violating both the 2-LLM-call budget and 300 ms critical-path latency cap. Bounded silent drift on zero-error-signal tasks is the unavoidable trade-off for cheap autonomy plus fast post-hoc containment.

6. Experiment

7-Day Falsification Test. Run an 80/20 randomized A/B split across the live 5,000 tasks/day queue (~1,000 memory-off control runs/day vs. 4,000 memory-enabled treatment runs/day, giving ~140 control human labels/week for power), plus 60 fault-injected sandbox runs (20 stale configs, 20 planted external-domain tickets, 20 cascading derivations flagged on Day 3).

  • Measured metrics: (1) Repeat-task step count and tool-retry rate, (2) 2% human rejection rate (treatment vs. control), (3) planted-domain action leakage, (4) % of 15 derived claims quarantined within 60 s of Day-3 flag, (5) p95 memory latency and daily memory LLM calls/run.
  • What proves the thesis wrong: Treatment increases human rejection rate over control, fails to cut repeat-task steps by ≥10%, leaks >0 actions to planted domains, quarantines <100% of single-source derived errors, or exceeds 300 ms p95 / 2.0 LLM calls/run.
